# 앱 스토어 심사용 가족 코드 정책

App Store 심사자가 가족 연결을 통과해 앱 본 화면을 확인할 수 있도록 하는 심사 한정 기능입니다.

---

## 왜 필요한가

가족 연결은 자녀 1명과 부모 최대 2명만 허용하고 한 사용자는 한 가족에만 속합니다. 데모 계정 하나의 코드를 심사 노트에 공유하면 재심사가 반복될 때 슬롯이 소진됩니다.

| 데모 계정 역할 | 연결 가능 횟수 | 소진 후 응답 |
|----------------|----------------|--------------|
| 자녀 | 2회 (부모 슬롯 2개) | `가족에는 부모를 최대 2명까지만 연결할 수 있습니다` |
| 부모 | 1회 | `이미 다른 가족과 연결된 부모입니다` |

심사자가 역할을 반대로 선택하면 `부모와 자녀만 가족으로 연결할 수 있습니다`로 즉시 막힙니다. 심사자는 원인을 알 수 없어 "가족 연결이 되지 않아 앱을 확인할 수 없다"로 리젝합니다.

---

## 동작

`APP_REVIEW_FAMILY_CODE`에 코드를 설정하면 `POST /api/v1/family/matches`가 그 코드를 특별 처리합니다.

- 기존 가족에 합류하지 않고 **심사자마다 새 1:1 데모 가족**을 만듭니다. 재심사가 반복되어도 소진되지 않습니다.
- 심사자와 **반대 역할**의 데모 구성원을 자동 생성합니다. 심사자가 자녀로 가입하면 데모 부모, 부모로 가입하면 데모 자녀가 붙습니다. 역할 선택 실수로 막히지 않습니다.
- 데모 부모는 **완료된 프로필과 여행 MBTI**(`healing_traveler`)를 가집니다. 완료 프로필이 없으면 심사자가 여행을 만들 수 없어 다시 막힙니다.
- 같은 심사자가 코드를 두 번 입력해도 오류 없이 현재 가족을 반환합니다.
- 코드 정규화는 일반 코드와 같아 `MSH-0901`과 `MSH0901`을 모두 인식합니다.
- 환경변수가 비어 있으면 기능이 완전히 꺼지고 해당 코드는 일반 코드 조회로 넘어갑니다.

데모 사용자는 실제 소셜 계정이 아니므로 `users.oauth_subject`에 `review-demo:` 접두사를 붙입니다. 카카오 회원번호는 숫자 문자열이라 충돌하지 않습니다.

### 데모 여행

데모 가족마다 여행 하나를 함께 만듭니다. **기간을 `오늘-2 ~ 오늘`로 잡아 여행 모드와 피드백을 동시에 엽니다.**

- 오늘이 기간에 포함되어 조회 시 `in_progress`가 되고 여행 모드와 AI 챗봇을 볼 수 있습니다.
- 종료일이 오늘이라 부모가 곧바로 피드백을 제출할 수 있습니다. 데모 가족은 부모가 한 명이므로 그 제출로 여행이 `completed`가 되고 효도 리포트가 생성되어 기록 탭까지 이어집니다.
- 3일치 코스에 경주 실제 좌표의 방문지 7곳(관광지·음식점·카페)과 일자별 경로 거리를 넣습니다. 좌표가 실제 위치라 지도와 주변 편의시설 조회도 동작합니다.
- 방문지는 **TourAPI를 호출하지 않고 고정값**으로 넣습니다. 심사 확인용이라 실제 조회가 필요 없고, 외부 API 장애가 심사를 막지 않아야 합니다.

**부모로 가입한 심사자에게 특히 중요합니다.** 여행 생성은 대표 자녀 권한이라 부모 심사자는 스스로 여행을 만들 수 없고, 이 데모 여행이 없으면 볼 화면이 없습니다.

## 심사 준비 절차

1. 서버 `.env`에 코드를 설정하고 컨테이너를 재생성합니다.

```bash
APP_REVIEW_FAMILY_CODE=MSH-0901
```

```bash
docker compose up -d --build --force-recreate app
```

2. App Store Connect의 **App Review Information → Notes**에 로그인부터 홈 진입까지의 단계를 적습니다. **선택할 역할과 코드를 명시**해야 합니다. 심사자는 한국어 UI를 읽지 못하므로 화면 녹화를 함께 첨부합니다.

심사자는 **어느 역할로 가입해도** 앱을 확인할 수 있습니다. 자녀로 가입하면 데모 부모의 완료 프로필로 새 여행을 만들 수 있고, 부모로 가입하면 데모 여행으로 여행 모드·피드백·기록을 확인할 수 있습니다.

3. 심사가 끝나면 환경변수를 비우고 컨테이너를 재생성합니다.

## 심사 후 정리

데모 데이터는 `review-demo:` 접두사로 찾습니다. 심사자 계정과 그 가족·여행이 함께 남아 있으므로 참조를 확인한 뒤 지웁니다.

```sql
-- 데모 사용자
SELECT id, role, display_name, created_at
FROM users
WHERE oauth_subject LIKE 'review-demo:%';

-- 데모 가족과 여행 (데모 사용자가 속한 가족 기준)
SELECT t.id, t.title, t.start_date, t.end_date, t.status
FROM trips t
JOIN family_members fm ON fm.family_id = t.family_id
JOIN users u ON u.id = fm.user_id
WHERE u.oauth_subject LIKE 'review-demo:%';
```

기록을 남겨도 문제가 없으면 그대로 두고 환경변수만 제거해도 됩니다. 코드가 꺼지면 새 데모 가족이 더 생기지 않습니다.

---

## 주의

- 이 기능이 켜져 있는 동안에는 코드를 아는 누구나 데모 가족을 만들 수 있습니다. **심사 기간에만 켜고 운영 중에는 반드시 끕니다.**
- 코드는 추측하기 어려운 값으로 정하고, 일반 사용자에게 발급되는 `MSH-0000` 형식과 겹치지 않는지 확인합니다. 형식이 같아도 심사용 코드가 먼저 처리되므로 같은 코드를 가진 실제 사용자가 있으면 그 사용자의 코드가 가려집니다.
