# /commit

스테이징되지 않은 변경사항을 포함해 현재 작업을 커밋합니다.
커밋 메시지는 `docs/conventions/commit.md` 컨벤션을 따릅니다.

## 실행 순서

### 1. 변경사항 파악

- `git status --short`로 변경된 파일 목록을 확인합니다.
- `git diff`로 실제 변경 내용을 확인합니다.
- 변경사항을 목적별로 분류하고, 관계없는 변경이 섞여 있으면 여러 커밋으로 나눌 계획을 세웁니다.
- `docs/harness/documentation-sync.md`의 커밋 전 체크리스트에 따라 코드 변경과 문서 변경이 함께 최신화되었는지 확인합니다.

### 2. 도메인 목록 최신화

- `src/main/kotlin/com/msdragon/backend/` 하위 패키지 구조를 스캔합니다.
- `docs/domains.md`의 도메인 목록과 비교합니다.
- 추가/삭제된 패키지가 있으면 `docs/domains.md`를 업데이트한 뒤 관련 변경과 함께 스테이징합니다.
- API, 도메인, DB, 공통 응답/예외, 패키지, 실행 설정 변경이 있으면 관련 `docs/` 문서도 함께 갱신합니다.

### 3. 커밋 타입 결정

`docs/conventions/commit.md`의 타입 목록을 참고하여 결정합니다.

- 새 기능: `feat`
- 버그 수정: `fix`
- 리팩터링: `refactor`
- 설정/환경: `setting`
- 문서: `docs`
- 빌드/의존성: `chore`
- 테스트: `test`

### 4. 스코프 결정

- 변경 파일들이 `docs/domains.md`의 단일 도메인에 속하면 스코프를 추가합니다.
- 여러 도메인에 걸치면 스코프 없이 작성합니다.

### 5. 커밋 메시지 작성 및 커밋

- 형식: `<type>(<scope>): <한국어 작업 내용>` 또는 `<type>: <한국어 작업 내용>`
- 목적이 같은 관련 파일만 `git add`로 스테이징합니다.
- 관계없는 변경사항이 남아 있으면 다음 목적의 커밋으로 반복합니다.
- 같은 파일 안에 여러 목적의 변경이 섞여 분리하기 어려운 경우에만 예외적으로 한 커밋에 포함합니다.
- `git commit`으로 커밋을 실행합니다.

## 주의사항

- `.env`, 시크릿, 인증 정보가 포함된 파일은 스테이징하지 않습니다.
- 커밋 메시지는 반드시 한국어로 작성합니다.
- `docs/domains.md`가 변경된 경우 관련 코드 변경과 같은 커밋에 포함합니다.
