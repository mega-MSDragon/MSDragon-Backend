# 여행 10계명 정책

여행 10계명 후보 제공, 문구 수정, 여행별 확정본 저장과 이후 서명 흐름의 기준입니다.

## 후보 제공

- 후보 원천은 `pledge_templates`의 `is_active=true` 데이터입니다.
- 서버 시작 시 와이어프레임 후보 문구를 기본 데이터로 추가하되 기존 문구와 운영 중 비활성 상태는 유지합니다.
- 후보 API는 전체 활성 후보를 섞은 뒤 중복 없이 10개를 반환합니다.
- 후보가 10개 미만이면 정상 화면을 구성할 수 없으므로 서버 설정 오류로 처리합니다.
- 후보 선택 결과는 저장하지 않습니다. 확정 전 화면 이탈 시 작성 내용이 초기화되는 와이어프레임 정책을 따릅니다.

## 확정본 저장

- 자녀가 문구를 확인·수정한 뒤 본인 서명 화면으로 이동하기 직전에 서버에 저장합니다.
- 확정본은 여행당 하나의 `trip_pledges`와 정확히 10개의 `pledge_items`로 구성합니다.
- 요청 배열 순서대로 `sort_order` 1~10을 부여합니다.
- 후보 템플릿 ID는 추적용으로 남기며, 템플릿 원문과 최종 문구가 같을 때만 `is_from_template=true`입니다.
- 사용자가 직접 작성한 문구는 `pledge_template_id=null`, `is_from_template=false`로 저장할 수 있습니다.
- 저장 직후 상태는 `reviewed`입니다.
- `draft`, `reviewed` 상태에서는 전체 교체가 가능하고 `signature_requested` 이후에는 문구를 수정할 수 없습니다.

## 권한

- 여행을 만든 자녀만 후보 조회와 확정본 저장을 할 수 있습니다.
- 후보 조회와 저장은 여행 상태가 `planning` 또는 `ready`일 때만 가능합니다.
- 이번 단계의 확정본 조회도 작성 자녀에게만 허용합니다.
- 자녀 서명 후 상태가 `signature_requested`가 되면 여행 참여 부모에게 조회 권한을 엽니다.

## 서명과 PDF 후속 정책

- 자녀가 먼저 서명한 뒤 참여 부모에게 서명을 요청합니다.
- 부모가 2명 참여하더라도 부모 중 최소 1명이 서명하면 10계명은 완료 상태가 됩니다.
- PDF 공유 조건은 `자녀 서명 완료 + 참여 부모 최소 1명 서명 완료`입니다.
- 각 사용자의 서명은 비트맵 파일 URL과 서명 시각으로 저장합니다.
- 서명 이미지 저장소, 전체 문서 비트맵 렌더링, PDF 생성 방식은 후속 구현에서 확정합니다.
