# 여행 모드 정책

여행 기간에 맞춘 상태 전환과 여행 모드 진입 API의 기준입니다.

## 이용 기간과 상태

- 날짜 기준 시간대는 `Asia/Seoul`입니다.
- 여행 모드는 `startDate` 00:00부터 `endDate` 23:59까지 이용할 수 있습니다.
- 시작일이 되면 코스와 여행 10계명 준비 여부에 관계없이 여행 상태를 `in_progress`로 변경합니다.
- 종료일 다음 날부터 여행 상태를 `completed`로 변경하고 여행 모드 진입을 막습니다.
- 시작 전에는 기존 `planning` 또는 `ready` 상태를 유지합니다.
- `stopped`, `archived` 상태는 날짜에 따라 다시 변경하지 않습니다.
- 별도 여행 시작 버튼과 상태 전환 스케줄러는 두지 않습니다. 여행 생성, 목록·상세·코스·여행 모드 조회처럼 여행 상태를 사용하는 요청에서 현재 서울 날짜에 맞춰 상태를 DB에 동기화합니다.
- 생성 자녀가 `POST /api/v1/trips/{tripId}/stop`을 호출하면 계획 종료일 전에도 `completed`로 수동 종료합니다.

## 접근 권한

- 로그인 사용자가 여행과 같은 가족에 연결되어 있으면 여행 모드에 접근할 수 있습니다.
- 해당 여행의 `trip_participants`에 선택되지 않은 같은 가족 구성원도 접근할 수 있습니다.
- 다른 가족의 사용자는 HTTP `200`, 본문 `status=403`으로 차단합니다.
- `stopped` 여행은 기간 안이어도 여행 모드에 다시 진입할 수 없습니다.

## 여행 중 편집

- 여행을 생성한 자녀만 여행 중 정보를 수정할 수 있습니다.
- 제목은 변경할 수 있고 도시는 고정하며, 기간은 변경 후에도 서울 기준 오늘을 포함해야 합니다.
- 참여 부모와 일자별 코스는 변경할 수 있습니다.
- 기간 또는 참여 부모가 바뀌어도 기존 코스와 경로는 일차 번호 기준으로 유지합니다. 기간이 줄면 뒤쪽 일차만 삭제하고 늘면 빈 일차를 추가합니다. 참여 부모가 바뀌면 여행 10계명과 모든 서명은 삭제합니다.
- 변경 저장 뒤 여행 기간에 오늘이 포함되므로 상태는 `in_progress`를 유지합니다.
- 종료일 다음 날 `completed`가 되면 기본정보와 코스를 더 이상 수정할 수 없습니다.

## 여행 모드 응답

- 클라이언트가 처음 표시할 현재 일차를 알 수 있도록 `currentDayNumber`, `currentTripDayId`를 반환합니다.
- 마지막 날 전용 UI 판단을 위해 `isLastDay`를 반환합니다.
- 헤더의 함께 가는 사람 표시에 사용할 `participants`를 반환합니다.
- 여행 10계명이 자녀와 참여 부모 최소 1명의 서명으로 완료되었는지 `pledgeCompleted`로 반환합니다.
- 날짜 탭 전환과 지도·일정 표시에 사용할 수 있도록 전체 일자별 경로와 방문지 `days`를 함께 반환합니다.
- 클라이언트는 `currentDayNumber`에 해당하는 일자를 처음 선택하고, 이후 사용자가 다른 날짜 탭을 선택하면 같은 응답의 `days`를 사용합니다.
- 마지막 날 평가 요청·제출 상태는 여행 모드 응답에 합치지 않고 `GET /api/v1/trips/{tripId}/feedback/status`에서 조회합니다.

## 주변 편의시설

- 카페는 `GET /api/v1/trips/{tripId}/nearby-cafes`에서 조회합니다.
- 공중화장실은 여행 모드 기본 응답과 분리된 `GET /api/v1/trips/{tripId}/nearby-restrooms`에서 조회합니다.
- 병원은 `GET /api/v1/trips/{tripId}/nearby-hospitals`, 약국은 `GET /api/v1/trips/{tripId}/nearby-pharmacies`에서 조회합니다.
- 같은 가족 구성원이 여행 기간 중 현재 위치를 전달해 사용할 수 있습니다.
- 공중화장실은 DB 적재 데이터, 카페·병원·약국은 Tmap POI 실시간 검색 결과를 사용합니다.
- 상세 조회 기준은 `docs/policy/nearby-support-facilities.md`를 따릅니다.

## AI 챗봇

- 같은 가족 구성원은 여행 기간 중 `GET/POST /api/v1/trips/{tripId}/chat/messages`를 사용할 수 있습니다.
- 대화는 사용자별·여행별로 분리하며 첫 질문에 세션을 자동 생성합니다.
- 현재 여행 코스와 장소 정보만 AI 문맥에 포함하고 부모 프로필·여행 MBTI는 보내지 않습니다.
- 상세 기준은 `docs/policy/travel-chat.md`를 따릅니다.

## 이번 구현 범위 밖

- 여행 모드 전용 체크리스트

체크리스트는 여행 모드 기본 진입 API와 분리해 후속 API로 구현합니다.

마지막 날 부모 평가 요청과 작성은 별도 피드백 API로 구현되었으며 `docs/policy/trip-feedback.md`를 따릅니다.
