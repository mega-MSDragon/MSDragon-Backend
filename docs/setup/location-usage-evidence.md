# 위치정보 이용 이력 증빙

## 기록 범위

- 좌표 및 여행 접근 검증 후 시설 조회를 시작하기 전에 `USE`를 저장합니다. 실패한 요청이나 AI 채팅 트랜잭션 롤백 이후에도 기록은 보존됩니다.
- Tmap 호출 직전 `TMAP`, 카페 이미지 TourAPI 호출 직전 `TOUR_API`의 `EXTERNAL_REQUEST_ATTEMPT`를 별도로 저장합니다. 이는 호출 시도이지 외부 수신 성공의 증명이나 법적 제3자 제공 판정은 아닙니다. 설정 오류나 네트워크 실패 때도 시도 이력이 남을 수 있습니다.
- 기록 저장 실패 시 해당 위치 처리/외부 호출을 진행하지 않습니다. TourAPI 보강 실패를 무시하는 로직 바깥에서 기록하므로 감사 저장 실패가 무시되지 않습니다.
- 현재 좌표, 토큰, 질문 본문은 기록하지 않습니다. 사용자·여행 ID는 기존 인증 및 요청에서 가져오며 취득 경로는 앱 단말 위치 기능입니다. 기기 OS/SDK는 추정하지 않습니다.
- AI 채팅이 주변 조회를 실제 호출할 때 같은 이력이 생성됩니다. 단순히 좌표를 전달했으나 주변 도구가 실행되지 않은 대화는 이 테이블의 이용 이벤트가 아닙니다.

## 배포와 캡처

현재 GitHub Actions 배포는 GitHub 호스팅 러너에서 EC2로 SSH 접속합니다. 보안 그룹 SSH 소스를 담당자 IP 하나로 제한하면 자동 배포 러너가 차단될 수 있습니다. 이 경우 허용된 담당자 환경에서 배포하거나, 별도 승인된 배포 접근 경로를 구성해야 합니다. 자동 배포를 위해 SSH를 전체 공개하지 않습니다.

운영 `ddl-auto=update` 배포 시 신규 테이블이 생성됩니다. 기존 데이터는 소급 생성하지 않습니다. 실제 앱에서 여행 기간 중 주변 시설을 조회한 뒤, 관리자 SSH 접속을 통해 PostgreSQL에서 다음 읽기 전용 쿼리를 실행합니다. DB 5432 포트를 외부에 열 필요는 없습니다.

```sql
SELECT id, user_id AS "이용자 식별값",
       acquisition_source AS "취득 경로",
       service_name AS "이용 서비스", event_type AS "기록 종류",
       external_recipient AS "외부 요청 대상",
       to_char(occurred_at AT TIME ZONE 'Asia/Seoul',
               'YYYY-MM-DD HH24:MI:SS') AS "이용일시(KST)"
FROM location_usage_logs
ORDER BY occurred_at DESC, id DESC
LIMIT 30;
```

`USE`는 서비스 이용 시작, `EXTERNAL_REQUEST_ATTEMPT`는 외부 API 요청 시도입니다. 제출 표의 제공받는 자란은 외부 API 처리 관계에 대한 검토를 거쳐 작성하며, 이 코드값을 법적 제공 대상이라고 단정하지 않습니다. 캡처에 테스트/예시 행을 실제 운영 기록처럼 넣지 않습니다.

## 보존 및 권한

- 앱에는 이력 조회·수정·삭제 API와 삭제 repository 메서드가 없습니다. 필드는 생성 후 갱신하지 않습니다. 이용자/여행 삭제와 연쇄 삭제되지 않습니다.
- 자동 삭제는 구현하지 않았습니다. 승인된 보존 기간이 정해지기 전에 이력을 임의로 삭제하지 않기 위한 선택입니다. 운영자는 적용할 보존 기간과 만료 후 정리 절차를 확정해야 합니다. 무기한 보관 정책을 뜻하지 않습니다.
- 애플리케이션 수준의 추가 전용 처리는 DB 관리자에 대한 위변조 방지가 아닙니다. 운영 DB 계정 권한 분리(앱 INSERT, 증빙 담당 SELECT, 기간 만료 정리는 별도 운영 권한), 보호된 백업 및 보존 설정은 운영에서 확인해야 합니다. 현재 테이블 소유자 계정으로 실행하는 구성에서는 권한을 제한했다고 기재하지 않습니다.
- 이 기능만으로 법정 보호조치 전체나 보존 정책 준수가 완료되었다고 기재하지 않습니다.
