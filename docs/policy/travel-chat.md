# 여행 모드 AI 챗봇 정책

여행 중 일정과 여행지 질문에 답하는 AI 챗봇의 서버 정책입니다.

## 이용 조건

- 서울 날짜 기준 여행 시작일부터 종료일까지 사용할 수 있습니다.
- 해당 여행과 같은 가족에 연결된 구성원만 접근할 수 있습니다.
- 세션과 대화 이력은 사용자별·여행별로 분리합니다. 가족 구성원끼리 서로의 대화를 공유하지 않습니다.
- 첫 질문을 보낼 때 활성 세션을 자동 생성합니다. 별도 세션 생성 API는 두지 않습니다.

## AI 문맥

질문을 보낼 때마다 현재 여행 데이터를 다시 읽어 세션의 `context_snapshot`을 갱신합니다. 코스를 수정한 뒤 질문해도 최신 일정이 반영됩니다.

문맥에 포함하는 값:

- 여행 ID, 제목, 도시, 시작일, 종료일, 현재 일차
- 일자별 날짜와 경로 거리·시간
- 방문 순서, 장소명, 카테고리, 주소, 전화번호, 소개, 도착 예정 시간, 체류 시간, 메모

이번 버전에서는 부모 프로필, 여행 MBTI, 성별, 연령대, 가족 구성원 이름을 OpenAI에 보내지 않습니다. `personalization_enabled`는 `false`로 저장합니다. 개인화 동의와 전달 범위가 확정되면 별도 정책으로 추가합니다.

## OpenAI 호출

- OpenAI Responses API `POST /v1/responses`를 사용합니다.
- 기본 모델은 비용을 고려해 `gpt-5.6-luna`로 정했습니다.
- 여행 안내는 복잡한 추론이 필요하지 않아 `reasoning.effort=none`, `text.verbosity=low`를 사용합니다.
- 답변은 최대 800 output token으로 제한합니다.
- 서버 DB가 대화 이력을 관리하므로 OpenAI 요청에는 `store=false`를 보냅니다.
- 사용자 DB ID를 직접 보내지 않고 SHA-256으로 변환한 값을 `safety_identifier`로 전달합니다.
- AI에는 저장된 최근 20개 메시지만 전달합니다. 전체 이력은 DB에 유지하고 조회 API에서 반환합니다.
- 별도 web search 도구는 사용하지 않습니다. 운영시간, 요금, 혼잡도처럼 바뀔 수 있는 정보는 현장 확인이 필요하다고 안내합니다.

## 답변 범위

- 여행 일정, 방문 순서, 장소 정보, 일반적인 여행 질문에 답합니다.
- 여행과 무관한 질문에는 여행 관련 질문을 요청합니다.
- 확인할 수 없는 사실은 만들지 않습니다.
- 응급 상황에서는 의료 판단을 하지 않고 119 신고와 앱의 주변 의료시설 기능을 안내합니다.

## 저장

- 사용자 질문과 AI 답변은 `chat_messages`에 저장합니다.
- AI 메시지의 `metadata`에는 OpenAI response ID, 모델명, token 사용량을 JSON 문자열로 저장합니다.
- OpenAI 호출이 실패하면 해당 요청에서 만든 세션과 사용자 질문을 함께 rollback합니다.

## 후속 범위

- 응답 streaming
- 대화 이력 pagination과 세션 종료
- 부모 프로필·여행 MBTI 기반 개인화
- 실시간 web search 또는 외부 관광 데이터 도구 호출
- token 사용량 기반 비용 제한과 사용자별 호출 제한
