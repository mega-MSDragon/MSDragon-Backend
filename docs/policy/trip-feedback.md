# 여행 피드백 정책

여행 마지막 날부터 자녀가 참여 부모에게 평가를 요청하고, 부모가 여행 소감을 제출할 때 적용하는 기준입니다.

## 작성 시점

- 날짜 기준 시간대는 `Asia/Seoul`입니다.
- 여행 종료일 00:00부터 평가 요청과 피드백 제출을 허용합니다.
- 종료일이 지난 뒤에도 별도 기한 없이 제출할 수 있습니다.
- 여행이 `completed` 또는 `archived` 상태여도 아직 제출하지 않은 참여 부모는 제출할 수 있습니다.

## 요청 정책

- 여행을 생성한 자녀만 평가를 요청할 수 있습니다.
- 요청 대상은 해당 여행에 참여했고 아직 피드백을 제출하지 않은 모든 부모입니다.
- `POST /api/v1/trips/{tripId}/feedback/requests`는 여러 번 호출해도 부모별 요청 이력을 한 건만 유지합니다.
- 이미 제출한 부모에게는 새 요청 이력을 만들지 않습니다.
- 부모는 자녀의 요청 이력이 없어도 마지막 날부터 직접 제출할 수 있습니다.

## 제출 정책

- 해당 여행의 참여 부모만 본인 피드백을 제출할 수 있습니다.
- 부모 한 명당 여행별 한 건만 저장합니다.
- 제출 후 수정하거나 다시 제출할 수 없습니다.

필수 항목:

| 항목 | 저장값 | 규칙 |
|------|--------|------|
| 전체 만족도 | `overallRating` | `0.0` 이상 `5.0` 이하, `0.5` 단위 |
| 여행 후 몸 상태 | `bodyCondition` | `comfortable`, `slightly_tired`, `very_tired` 중 하나 |
| 가장 좋았던 장소 | `bestTripStopId` | 해당 여행에 저장된 방문지 ID |

선택 항목:

- 좋았던 점 태그
- 다음 여행에서 개선할 점 태그
- 자유 의견 200자 이내

## 태그

좋았던 점:

| 화면 문구 | API 값 |
|-----------|--------|
| 걷기 적당했어요 | `walking_comfortable` |
| 쉬는 시간이 좋았어요 | `rest_time_good` |
| 풍경이 좋았어요 | `scenery_good` |
| 이동이 편했어요 | `transport_comfortable` |
| 음식이 맛있었어요 | `food_good` |
| 앉을 곳이 많았어요 | `seating_sufficient` |

다음 여행에서 개선할 점:

| 화면 문구 | API 값 |
|-----------|--------|
| 쉬는 시간이 더 필요해요 | `more_rest_needed` |
| 계단/경사가 많았어요 | `many_stairs_or_slopes` |
| 이동 시간이 길었어요 | `long_travel_time` |
| 사람이 많았어요 | `crowded` |

- 같은 태그를 중복 제출할 수 없습니다.
- 좋았던 점과 개선할 점의 태그 그룹을 바꾸어 보낼 수 없습니다.

## 베스트 장소 저장

- 제출 시 `bestTripStopId`가 해당 여행의 방문지인지 검증합니다.
- DB에는 방문지 ID와 제출 당시 장소명을 함께 저장합니다.
- 코스가 나중에 변경되더라도 제출 당시 장소명을 보여줄 수 있도록 장소명은 스냅샷으로 보존합니다.
- `bestTripStopId`에는 FK를 두지 않습니다. 제출 시점의 서비스 검증으로 소속을 보장하고, 이후 코스 전체 교체가 피드백 삭제로 이어지지 않게 합니다.

## 제출 현황과 리포트 준비

- 여행 생성 자녀와 참여 부모는 `GET /api/v1/trips/{tripId}/feedback/status`에서 부모별 요청·제출 시각을 조회합니다.
- 참여 부모가 모두 제출하면 `reportReady=true`를 반환합니다.
- `reportReady`는 효도 리포트를 만들 수 있는 조건만 뜻합니다. 실제 리포트 생성과 조회는 별도 작업으로 구현합니다.

## 여행 수정 영향

- 여행 기간 또는 참여 부모 구성이 바뀌면 기존 평가 요청과 피드백을 모두 삭제합니다.
- 기간 변경은 작성 가능 시점을 바꾸고, 참여 부모 변경은 제출 대상을 바꾸므로 새 조건에서 다시 요청·제출해야 합니다.
- 코스만 수정할 때는 피드백을 삭제하지 않습니다. 이미 제출한 베스트 장소는 장소명 스냅샷으로 유지합니다.
- `completed`, `archived` 여행은 기본정보와 코스를 수정할 수 없으므로 제출 완료 후 정책이 다시 바뀌지 않습니다.
