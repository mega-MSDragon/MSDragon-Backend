# 회원가입 온보딩 정책

확정 iOS 디자인의 로그인, 회원가입, 가족 연결 흐름을 서버 API와 연결하는 기준입니다.

## 화면과 API 흐름

1. iOS는 카카오 또는 Apple 소셜 인증 토큰으로 `POST /api/v1/auth/social-login`을 호출합니다.
2. 미가입 사용자는 응답의 `signupToken`을 보관합니다.
3. 약관, 역할, 이름, 연령대, 성별은 앱에서 단계별로 입력하고 마지막 `가입 완료` 전까지 로컬 상태로 유지합니다.
4. `POST /api/v1/auth/signup/complete`를 한 번 호출해 사용자와 약관 결정을 저장하고 서비스 토큰을 발급받습니다.
5. `POST /api/v1/family/code`로 내 초대 코드를 표시합니다.
6. 상대방 코드를 받은 사용자는 `POST /api/v1/family/matches`로 가족을 연결합니다.
7. 가족 연결 완료 전에는 홈으로 진입하지 않습니다. 재로그인하거나 상대방의 코드 입력을 기다리는 동안 `GET /api/v1/family`로 상태를 확인합니다.

## 약관

| 약관 | 필수 여부 | 서버 타입 | 최초 버전 |
|------|-----------|-----------|-----------|
| 개인정보 수집 및 이용 | 필수 | `privacy_collection` | `v1` |
| 위치 기반 편의시설 안내 | 선택 | `location_based_facility` | `v1` |

- 필수 개인정보 약관은 `privacyConsentAgreed=true`여야 회원가입할 수 있습니다.
- 선택 위치 약관은 값을 생략하면 `false`로 처리합니다.
- 클라이언트가 약관 버전을 보내지 않습니다. 서버가 현재 버전을 결정해 `user_consents`에 저장합니다.
- 약관을 개정하면 서버 버전을 올리고 같은 사용자·약관 종류의 새 버전 결정을 추가합니다. 과거 행은 덮어쓰지 않습니다.

## 역할별 입력 정책

| 역할 | 연령대 |
|------|--------|
| 자녀 | `10s`, `20s`, `30s`, `40s`, `50s`, `60s_plus`, `undisclosed` |
| 부모 | `30s`, `40s`, `50s`, `60s`, `70s`, `80s`, `90s_plus`, `undisclosed` |

- 이름은 공백만 입력할 수 없으며 앞뒤 공백을 제거해 최대 50자로 저장합니다.
- 성별은 `female`, `male`, `undisclosed`를 사용합니다. 요청에서 생략해도 `undisclosed`로 저장합니다.

## 가족 코드

- 사용자별 고정 코드이며 저장 형식은 `MSH-0000`입니다.
- 숫자 범위는 `0000`부터 `9999`까지입니다.
- 입력 요청은 `MSH0001`, `MSH-0001`을 모두 허용합니다.
- 가족당 자녀는 1명, 부모는 최대 2명까지 연결할 수 있습니다.
