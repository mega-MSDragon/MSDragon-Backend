# 여행 10계명 정책

여행 10계명 후보 제공, 문구 수정, 여행별 확정본 저장과 이후 서명 흐름의 기준입니다.

## 후보 제공

- 후보 원천은 `pledge_templates`의 `is_active=true` 데이터입니다.
- 서버 시작 시 와이어프레임 후보 문구를 기본 데이터로 추가하되 기존 문구와 운영 중 비활성 상태는 유지합니다.
- 후보 API는 전체 활성 후보를 섞은 뒤 중복 없이 10개를 반환합니다.
- 후보가 10개 미만이면 정상 화면을 구성할 수 없으므로 서버 설정 오류로 처리합니다.
- 후보 선택 결과는 저장하지 않습니다. 확정 전 화면 이탈 시 작성 내용이 초기화되는 와이어프레임 정책을 따릅니다.

## 확정본 저장

- 자녀가 문구를 확인·수정한 뒤 본인 서명 화면으로 이동하기 직전에 서버에 저장합니다.
- 확정본은 여행당 하나의 `trip_pledges`와 정확히 10개의 `pledge_items`로 구성합니다.
- 요청 배열 순서대로 `sort_order` 1~10을 부여합니다.
- 후보 템플릿 ID는 추적용으로 남기며, 템플릿 원문과 최종 문구가 같을 때만 `is_from_template=true`입니다.
- 사용자가 직접 작성한 문구는 `pledge_template_id=null`, `is_from_template=false`로 저장할 수 있습니다.
- 저장 직후 상태는 `reviewed`입니다.
- `draft`, `reviewed` 상태에서는 전체 교체가 가능하고 `signature_requested` 이후에는 문구를 수정할 수 없습니다.

## 권한

- 여행을 만든 자녀만 후보 조회와 확정본 저장을 할 수 있습니다.
- 후보 조회와 저장은 여행 상태가 `planning` 또는 `ready`일 때만 가능합니다.
- 작성 자녀는 확정본 저장 직후부터 조회할 수 있습니다.
- 자녀 서명 후 상태가 `signature_requested`가 되면 여행 참여 부모에게 조회와 서명 권한을 엽니다.
- 여행에 참여하지 않은 가족 구성원은 조회하거나 서명할 수 없습니다.

## 서명 정책

- 자녀가 먼저 서명한 뒤 참여 부모에게 서명을 요청합니다.
- 부모가 2명 참여하더라도 부모 중 최소 1명이 서명하면 10계명은 완료 상태가 됩니다.
- 완료 상태가 된 뒤에도 아직 서명하지 않은 다른 참여 부모는 본인 서명을 추가할 수 있습니다.
- 모든 여행 참여자는 현재까지 제출된 자녀와 부모의 전체 서명을 동일하게 조회합니다.
- 제출된 서명은 수정하거나 덮어쓸 수 없습니다.
- 서명 요청은 data URI prefix 없는 PNG Base64 문자열로 받습니다.
- 서버는 Base64를 디코딩하고 PNG 형식과 최대 512KB 크기를 검증한 뒤 PostgreSQL `bytea`에 저장합니다.
- `completed_at`은 첫 참여 부모 서명으로 완료 조건을 충족한 시각이며 이후 추가 부모 서명으로 변경하지 않습니다.

## 참여 부모 변경

- 여행 수정에서 참여 부모 ID 집합이 바뀌면 기존 `trip_pledges`, `pledge_items`, `pledge_signatures`를 모두 삭제합니다.
- 새 참여자 구성에서는 자녀가 문구 작성과 본인 서명부터 다시 진행하고, 새로 선택된 부모가 다시 서명합니다.
- 제목, 도시, 날짜만 변경되고 참여 부모 구성이 같으면 기존 확정본과 서명을 유지합니다.
- 참여 부모 변경과 10계명 초기화는 같은 트랜잭션에서 처리하므로 여행 수정이 실패하면 기존 데이터도 유지됩니다.

## PDF 생성 정책

- PDF 공유 조건은 `자녀 서명 완료 + 참여 부모 최소 1명 서명 완료`입니다.
- 모든 여행 참여자는 같은 PDF를 조회하며, 조회 시점까지 추가된 전체 참여자 서명이 포함됩니다.
- 서버는 저장된 문구, 여행 제목과 기간, 전체 서명 데이터를 HTML 템플릿에 합성하고 A4 PDF로 변환합니다.
- 계약 번호는 `작성 연도-여행 10계명 ID(최소 2자리)`로 요청 시 계산합니다. 예: `2026-01`.
- 모든 참여자가 같은 PDF를 공유하므로 서약 문장은 특정 부모 이름 대신 `우리 가족은`으로 통일합니다.
- 서명 영역에는 조회 시점까지 제출한 자녀와 모든 참여 부모의 서명 및 `서약 완료` 표시를 함께 넣습니다.
- 성공 응답은 `application/pdf` 원본 바이트이며 클라이언트가 앱 내 미리보기, 저장, 공유에 사용합니다.
- HTML 템플릿과 PDF는 요청 시 생성하며 DB나 외부 파일 저장소에 완성본을 저장하지 않습니다.
- 동적 문구는 HTML 문자열 연결이 아니라 DOM의 텍스트 노드로 삽입해 사용자 입력이 마크업으로 실행되지 않도록 합니다.

### HTML 교체 계약

확정 템플릿 경로는 `src/main/resources/templates/pledge/trip-pledge.html`입니다. 이후 세부 디자인을 교체할 때 아래 ID를 유지합니다.

| ID | 서버가 삽입하는 값 |
|----|--------------------|
| `document-number` | 작성 연도와 여행 10계명 ID로 만든 계약 번호 |
| `written-date`, `written-date-copy` | 확정 문구 검토일 |
| `document-title` | 10계명 문서 제목 |
| `trip-title` | 여행 제목 |
| `trip-period` | 여행 시작일과 종료일 |
| `pledge-items` | 순서가 보존된 문구 10개 |
| `signature-list` | 자녀 우선, 부모 서명 시각순의 전체 서명 |

- 템플릿은 OpenHTMLtoPDF가 지원하는 인쇄용 CSS 범위에서 작성하고 JavaScript, flex, grid에 의존하지 않습니다.
- 한 페이지 A4 출력을 기본으로 하며 실제 서비스 문구와 최대 3명 서명으로 디자인을 검증합니다.
- 디자인만 바뀌는 경우 서버 Kotlin 코드와 API 계약은 변경하지 않습니다.
