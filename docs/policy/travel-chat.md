# 여행 모드 AI 챗봇 정책

여행 중 일정과 여행지 질문에 답하는 AI 챗봇의 서버 정책입니다.

## 이용 조건

- 서울 날짜 기준 여행 시작일부터 종료일까지 사용할 수 있습니다.
- 해당 여행과 같은 가족에 연결된 구성원만 접근할 수 있습니다.
- 세션과 대화 이력은 사용자별·여행별로 분리합니다. 가족 구성원끼리 서로의 대화를 공유하지 않습니다.
- 첫 질문을 보낼 때 활성 세션을 자동 생성합니다. 별도 세션 생성 API는 두지 않습니다.

## AI 문맥

질문을 보낼 때마다 현재 여행 데이터를 다시 읽어 세션의 `context_snapshot`을 갱신합니다. 코스를 수정한 뒤 질문해도 최신 일정이 반영됩니다.

문맥에 포함하는 값:

- 여행 ID, 제목, 도시, 시작일, 종료일, 현재 일차
- 일자별 날짜와 경로 거리·시간
- 방문 순서, 장소명, 카테고리, 주소, 전화번호, 소개, 도착 예정 시간, 체류 시간, 메모
- 방문지 ID, 좌표, 홈페이지, 추천 이유와 추천 태그

이번 버전에서는 부모 프로필, 여행 MBTI, 성별, 연령대, 가족 구성원 이름을 OpenAI에 보내지 않습니다. `personalization_enabled`는 `false`로 저장합니다. 개인화 동의와 전달 범위가 확정되면 별도 정책으로 추가합니다.

## OpenAI 호출

- OpenAI Responses API `POST /v1/responses`를 사용합니다.
- 기본 모델은 비용을 고려해 `gpt-5.6-luna`로 정했습니다.
- 여행 안내는 복잡한 추론이 필요하지 않아 `reasoning.effort=none`, `text.verbosity=low`를 사용합니다.
- 답변은 최대 800 output token으로 제한합니다.
- 서버 DB가 대화 이력을 관리하므로 OpenAI 요청에는 `store=false`를 보냅니다.
- 사용자 DB ID를 직접 보내지 않고 SHA-256으로 변환한 값을 `safety_identifier`로 전달합니다.
- AI에는 저장된 최근 20개 메시지만 전달합니다. 전체 이력은 DB에 유지하고 조회 API에서 반환합니다.
- Responses API function calling으로 서버가 허용한 최신 여행 일정, 코스 방문지, 주변 시설만 조회합니다.
- TourAPI 장소인 경우 방문지 상세 도구가 기존 상세 조회 서비스를 호출해 소개·이미지·이용 정보·무장애 정보를 갱신합니다. 외부 ID가 없거나 TourAPI 보강 조회가 실패한 방문지는 저장된 코스 스냅샷으로 답변을 계속합니다.
- 주변 시설 도구는 요청에 함께 전달된 현재 좌표로 기존 카페·공중화장실·병원·약국 서비스를 호출합니다. 좌표 자체는 모델 입력에 넣지 않습니다.
- 주변 시설 거리는 직선거리(m)이며 도보 시간처럼 표현하지 않습니다.
- 별도 web search 도구는 사용하지 않습니다. 운영시간, 요금, 혼잡도처럼 바뀔 수 있는 정보는 현장 확인이 필요하다고 안내합니다.

## 말투

- 챗봇 이름은 `물어봐용`입니다.
- 답변은 짧고 따뜻한 한국어로 작성합니다.
- 화면 시안처럼 `~해용`, `~있어용`, `~좋아용` 어미를 자연스럽게 사용하되 모든 문장에 강제하지 않습니다.
- 이모지는 꼭 필요한 경우 한 개 이하로 사용합니다.

## 질문 가능 범위

### 현재 여행 일정과 코스

서버에 저장된 최신 여행 데이터를 기준으로 답합니다.

- 오늘 또는 특정 일차의 방문 일정
- 방문 순서와 다음 방문지
- 장소별 도착 예정 시간과 체류 시간
- 일자별 총 이동 거리와 예상 이동 시간
- 방문지에 작성한 메모
- 여행 제목, 도시, 시작일과 종료일

예시:

- `오늘 일정 알려줘`
- `두 번째로 가는 곳이 어디야?`
- `첨성대에 몇 시쯤 도착해?`
- `카페에 적어둔 메모 알려줘`

### 현재 코스에 포함된 방문지 정보

- 장소명, 카테고리, 주소, 전화번호, 홈페이지
- 장소 소개와 추천 이유
- TourAPI가 제공하는 이미지, 이용 정보, 무장애 정보
- 서버에 저장된 추천 태그

TourAPI에 값이 없거나 사용자가 직접 추가한 장소는 저장된 코스 정보까지만 답합니다. 운영시간이나 입장료처럼 원천 응답으로 확인되지 않는 내용은 추측하지 않습니다.

예시:

- `해운대는 어떤 곳이야?`
- `이 장소 전화번호 알려줘`
- `휠체어로 이용할 수 있어?`

`여기 어떤 곳이야?`처럼 장소가 불분명하면 정확한 장소명을 다시 물을 수 있습니다. 현재 요청에는 사용자가 보고 있는 방문지 ID가 포함되지 않습니다.

### 현재 위치 주변 시설

클라이언트가 질문과 함께 `latitude`, `longitude`를 전달했을 때만 답할 수 있습니다.

- 주변 카페
- 주변 공중화장실
- 주변 병원
- 주변 약국
- 병원과 약국을 합친 의료시설 목록
- 가까운 순으로 1~10개 조회

예시:

- `가까운 화장실 어디야?`
- `주변 카페 3곳 알려줘`
- `근처 의료시설 알려줘`

현재 거리는 직선거리(m)입니다. 실제 도보 시간, 도보 경로, 계단 유무는 보장하지 않습니다. 위치가 전달되지 않으면 AI는 위치 정보가 필요하다고 안내합니다.

### 일반적인 여행 안내

실시간 정보나 개인 데이터를 요구하지 않는 간단한 여행 질문에는 일반 지식으로 답할 수 있습니다.

- 여행 준비물과 기본 주의사항
- 관광지 이용 예절
- 무리하지 않는 일반적인 이동·휴식 팁

일반 지식 답변은 프로젝트 DB나 외부 API 조회 결과가 아닙니다.

## 질문 불가 범위

### 실시간 정보

현재 web search, 날씨, 실시간 교통 API는 연결되어 있지 않습니다.

- 현재 또는 미래 날씨
- 실시간 교통, 혼잡도, 대기시간
- 실시간 영업 여부와 임시 휴무
- 실시간 입장료, 행사 일정, 좌석·재고
- 대중교통 도착 정보

### 현재 코스 밖의 장소 탐색

- 코스에 없는 새로운 관광지 검색
- 실시간 맛집 추천
- 숙소 검색과 추천
- 사용자의 현재 위치를 기준으로 한 일반 관광지 추천

코스 편집 화면의 장소 검색·추천 API는 AI 도구로 연결하지 않았습니다.

### 앱 데이터 변경과 외부 행동

AI는 조회만 할 수 있으며 아래 작업을 실행하지 않습니다.

- 여행 생성, 수정, 중단, 삭제
- 코스 방문지 추가, 삭제, 순서 변경
- 메모 작성이나 수정
- 예약, 결제, 전화 연결
- 길 안내 또는 내비게이션 실행

### 개인화되지 않은 항목

현재 OpenAI에 부모 프로필과 가족 개인정보를 보내지 않으므로 아래 질문은 지원하지 않습니다.

- 부모 성향과 여행 MBTI를 반영한 대화
- 부모 건강 상태나 개인 취향을 근거로 한 판단
- 가족 구성원 이름과 관계를 이용한 맞춤 답변
- 다른 가족 구성원의 채팅 내용 조회

### 의료 판단과 응급 상황

- 증상 진단, 약 추천, 치료 방법 안내
- 특정 병원의 진료 가능 여부나 응급실 운영 보장

응급 상황에는 의료 판단을 하지 않고 119 신고와 앱의 주변 의료시설 기능 이용을 안내합니다.

### 여행과 무관한 질문

일반 상식, 코딩, 과제, 금융·법률 상담처럼 여행과 관계없는 질문에는 여행 관련 질문을 요청합니다.

## 클라이언트·디자인 반영 기준

- 챗봇은 여행 시작일부터 종료일까지 여행 모드에서만 노출합니다.
- 주변 시설 질문을 보낼 때는 위치 권한을 확인하고 위도와 경도를 함께 전송합니다.
- 위치 권한이 없으면 주변 시설 추천 칩을 숨기거나, 선택 시 위치 권한 안내를 먼저 표시합니다.
- 거리 표시는 `도보 N분`이 아니라 `직선거리 N m` 기준으로 사용합니다.
- AI 답변은 일반 텍스트이므로 장소 목록 개수나 문장 형태가 항상 같다고 가정하지 않습니다.
- 추천 질문은 `여기 어떤 곳이야?`, `가까운 화장실 어디야?`, `오늘 일정 알려줘`처럼 현재 지원 범위 안에서 제공합니다.
- 사용자별 대화이므로 같은 가족이라도 서로의 채팅 이력을 볼 수 없습니다.
- API의 실제 HTTP가 `200`이면 응답 본문의 `success`와 `status`를 확인하고, OpenAI·TourAPI·Tmap 실패는 실제 HTTP `500`으로 처리합니다.

## 저장

- 사용자 질문과 AI 답변은 `chat_messages`에 저장합니다.
- AI 메시지의 `metadata`에는 OpenAI response ID, 모델명, token 사용량을 JSON 문자열로 저장합니다.
- OpenAI 호출이 실패하면 해당 요청에서 만든 세션과 사용자 질문을 함께 rollback합니다.

## 후속 범위

- 응답 streaming
- 대화 이력 pagination과 세션 종료
- 부모 프로필·여행 MBTI 기반 개인화
- 실시간 web search 또는 코스 밖 관광지 검색
- token 사용량 기반 비용 제한과 사용자별 호출 제한
